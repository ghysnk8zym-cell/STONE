# Internationalisation and copy

## Routes and language choice

`src/i18n/routing.ts` defines `ru` (default) and `en`, always-prefixed paths and
`localeDetection: false`. Unprefixed entry routes resolve to Russian; browser
language does not silently change the site. Product slugs are identical in both
languages. `src/i18n/navigation.ts` exports the locale-aware Link/router/redirect;
use these for application navigation. `src/middleware.ts` composes the route gate
and next-intl. Server actions use the validated request locale.

`LanguageSwitch.tsx` preserves pathname and query parameters, including repeated
query keys, and uses `router.replace` with the target locale. next-intl writes the
manual-choice `NEXT_LOCALE` cookie. The switch is an approved addition absent from
Figma; its accessible label includes the visible RU/EN text and target language.

## Three content sources

| Source                                 | Ownership and behavior                                                                                                                                                                                                |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `messages/en.json`, `messages/ru.json` | UI labels, validation/error/status copy, and default Home text. `src/i18n/request.ts` loads the requested dictionary.                                                                                                 |
| `product_translation`                  | Product names/descriptions for each locale. The seed obtains initial translations from messages; subsequent admin edits are database content. Stable slugs, dimensions and cents are not translated strings.          |
| `site_content`                         | Optional overrides for the 18 allowed Home text keys in each locale. Admin saves plain text with stale-value checks; restore removes the override and falls back to messages. It is not a general CMS or HTML editor. |

`src/server/content/home.ts` merges only allowed Home overrides. Home uses
request-time data so an edit is visible without the old five-minute ISR delay.
There is no database fallback for a configured-but-broken database: errors must
remain visible. With no database configured, public content uses its static seed.
Custom-request specifications keep their immutable EN/RU name snapshot; later
catalog translation edits do not rewrite those historical records.

## Types, parity and formatting

- `src/i18n/global.d.ts` extends next-intl `AppConfig` from the English dictionary
  and routing locales. Add a key in both dictionaries in the same change.
- `tests/unit/messages.test.ts` checks identical leaf keys and nonempty values;
  `client-messages` tests keep the internal styleguide dictionary out of the client
  payload. ESLint rejects unlocalized JSX text. These checks cannot judge grammar.
- Use ICU parameters and next-intl translations rather than concatenating UI
  sentences. Do not replace dynamic customer/user content with translation keys.
- Currency uses locale-aware `useFormatter` / `Intl.NumberFormat` with USD. Product
  prices are cents per square metre; custom quotes are cents per piece. Store
  numeric cents and format at the boundary; never parse a displayed currency value.
- Date display uses explicit UTC in order/admin history to avoid server/browser
  timezone drift; quantity/dimension input follows each form's documented parser.
  `Intl.Collator` sorts visible material/finish labels by locale.
- Inter supplies body Latin/Cyrillic. Lusitana supplies Latin display text; PT
  Serif is the Cyrillic fallback. `src/app/fonts.ts` and font CSS preserve that split.

## Copy review and changes

Russian copy is still a draft awaiting owner review. Automated parity, overflow
and accessibility checks do not establish editorial acceptance. Review actual
screens at 1440/1024/390, plurals, long validation messages, monetary units and
disabled/demo wording. Never imply an email was sent, payment was collected or a
public request was submitted when that capability is absent.

For a copy change: identify the correct source above; update both message files
where applicable; run parity/type/lint checks; inspect both locales in the affected
state. Do not reseed to overwrite an existing database translation. Home override
restore is an explicit admin action, not an automatic consequence of message edits.
